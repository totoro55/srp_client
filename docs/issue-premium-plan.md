# План: премия за выдачу товара, версия 1

Корзина — показатель «Выдача товара», код `release`. Id корзины в запросе не зашивать. Сейчас считается только рабочая версия 1, таблица параметров `basket_data.release_v1`. Черновик версии 2 те же параметры объявляет, но таблицы и формулы ещё нет: в снимок он не пишет.

Версия 1 не делит тариф по категории, изделию и каналу. На РРС два числа: `quantity` — премия за количество, `volume` — премия за объём. На филиале один коэффициент `release_coef`, «Коэффициент за выдачу». Оси `tariff_axis` у версии нет.

Данные документа — `raw.sale`. Это та же таблица, что у продажи. Отдельного документа выдачи нет: `type_document` продажу и выдачу не разделяет.

## Кому засчитывается строка

Выдачу получает `author2`. Пустой `author2` в премию не входит.

Филиал строки — не филиал документа. Это филиал сотрудника по `raw.hr_ktu` на дату документа: последняя строка, у которой `date_modified` не позже этой даты, в том числе из предыдущего месяца. Нет такой строки или филиал в ней не uuid — документ в премию не входит. Смена должности на том же филиале начинает новый отрезок: операция до `date_modified` остаётся на предыдущей строке.

РРС берётся у этого филиала. В расчёт входят только РРС, у которых на месяц подключена версия 1. Подключение — последняя запись `basket_connections` с периодом не позже месяца.

## Формула версии 1

Ставки РРС — последняя строка `basket_data.release_v1` с периодом не позже месяца. Нет строки или пустая ставка количества либо объёма — документ этого РРС не входит.

Коэффициент филиала — последняя запись `release_coef` с периодом не позже месяца. Записи нет — в формуле единица. Ноль допустим: премия строки тогда ноль.

В снимок пишется уже готовый тариф. Коэффициент отдельной колонкой не хранится.

```
тариф количества = ставка quantity × release_coef
тариф объёма     = ставка volume × release_coef
премия           = ROUND(тариф количества × count + тариф объёма × объём продажи, 2)
```

`count` — количество выданного товара, `volume` продажи — объём. Каналы, СТМ, безнал и множитель ×2 к выдаче не применяются. Округление одно, до копеек, как у продажи.

Строка с нулевым объёмом остаётся: объёмная часть даёт ноль, количественная считается. В октябре 2026 пустого `author2`, пустого количества и пустого объёма нет; нулевой объём есть у 95 строк из 1 094 450.

## Таблица снимка

Одна таблица на все версии выдачи: `main.release_premium_lines`. Версия 2 и следующие пишут сюда же, своим запросом и своим `version_id`. В таблицу продажи эти строки не попадают.

Вид как у `main.sale_premium_lines`: в строке готовые тарифы и готовая премия, коэффициентов нет. Колонок канала и способа расчёта нет — версии 1 они не нужны. Ось появится, когда версия начнёт считать по категории или изделию.

| Колонка | Смысл |
| --- | --- |
| `period` | Первое число месяца |
| `territory_uuid` | РРС филиала сотрудника |
| `branch_uuid` | Филиал по штатному расписанию |
| `employee_uuid` | `author2` |
| `version_id` | Версия, которая посчитала строку |
| `category_code` | Категория из `raw.sale.category`, для группировки детализации |
| `quantity_tariff` | Готовый тариф за количество |
| `volume_tariff` | Готовый тариф за объём |
| `item_count` | `count` |
| `volume` | Объём продажи |
| `premium` | Премия строки, до копеек |
| `link_doc`, `document_number`, `document_date` | Документ |
| `product_name` | `raw.sale.name_product`, пусто если названия не было |
| `calculated_at` | Когда посчитали строку |

Ключ строке не нужен: повторный пересчёт месяца удаляет его строки и пишет заново. Индекс тот же, что у продажи: `(period, branch_uuid, employee_uuid)`.

## Запись

Запрос версии 1 только читает, по образцу `sale-premium-category.sql`. В таблицу его вставляет пересчёт: одна транзакция, удалить строки месяца этой версии, вставить результат. Закрытый месяц не пересчитывается. Сохранение коэффициента или параметров само пересчёт не запускает.

Пока формула есть только у версии 1. Пересчёт месяца удаляет и пишет строки тех версий, для которых запрос уже есть. Подключённая версия без запроса строк не получает.

## Детализация

Экран тот же, что у продажи, не макет `IssueBonusDetail` с двумя суммами и сортировкой. Читается снимок, не `raw.sale` на каждый клик.

Группы: по категории, внутри по сумме по убыванию; по документу, документы по дате по убыванию. В строке название товара, категория, документ. Нажатие на документ копирует номер. Расчёт одной строкой, оба готовых тарифа уже с коэффициентом: `10 ₽ × 2 шт + 200 ₽ × 0,15 м³`. Сумма строки — `premium`. Канала и значка ×2 нет.

Широкий экран листает страницы, узкий добирает порциями по 20. Первая загрузка без данных — скелетон. Повторный запрос уже показанный список скелетоном не заменяет. Итог в шапке списка не считается.

В кабинете филиала сумма выдачи по сотруднику — сумма `premium` снимка за даты отрезка штатного расписания, как премия за продажу.
